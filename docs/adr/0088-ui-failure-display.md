# 0088. Failure display in the UI: no token, stale token, startup and shutdown, storage states, value errors
- Status: Accepted ([OURS]: items 1–4 except the values, 6); Accepted (OD-6) ([DEFAULT]: item 3 — D-80; item 4, item 5, item 6 — texts, D-81)
- Label: [OURS]; [DEFAULT] (D-80 — the auto-retry deadline; D-81 — texts and verbatim wording, Q-65)
- Date: 2026-10-27
- CUJ: CUJ1, CUJ2, CUJ3, CUJ5, CUJ12, CUJ13, CUJ16; ADR 0011 item 6 [USER]
- Closes Q-39; partly Q-65

## Context
The UI is an API client: all refusals arrive as codes (ADR 0062, 0063). The owner's decision (ADR 0011 item 6): the user learns about "read-only" and "storage error" when an action fails; the state is not shown in advance. ADR 0063 item 1: there is no state resource. The brief's texts: «Сохранение не выполнено: база доступна только для чтения» ("Saving failed: the database is read-only"), «ошибка хранилища, обратитесь к оператору» ("storage error, contact the operator"), «нужна новая ссылка из вывода сервера» ("a new link from the server output is needed") (CUJ13). UI strings below are quoted in Russian, the language of the interface; English glosses are in parentheses.

## Decision
1. [OURS] No token when the page loads (neither a fragment nor a stored token): «Нет ссылки для входа. Откройте ссылку, которую сервер напечатал при запуске» ("No sign-in link. Open the link the server printed at startup"), no forms and no results, no requests to the API.
2. [OURS] Q-39. 401 `unauthorized` with a presented token: the token is deleted, the action is not performed (401 arrives before the body is read, ADR 0063 item 7), the display is «Ссылка устарела: сервер был перезапущен. Нужна новая ссылка из вывода сервера» ("The link is stale: the server was restarted. A new link from the server output is needed"); the page does not reload, the form, what was entered in it and the results stay on screen; until there is a new link, actions make no requests and repeat the same text; a new link pasted in the same tab is accepted without a reload (ADR 0086 item 1), the previous action is not repeated. The reason is not made more specific: the server does not distinguish kinds of unrecognized token (ADR 0065 item 6), and after a restart this is the only reason for a UI token. The page polls nothing itself (item 7): an open tab learns of the restart at the first action.
3. [DEFAULT] (D-80) 503 `server_starting` (`Retry-After: 5`, ADR 0063 item 8): the request was not executed, a retry is safe; the UI shows «Сервер запускается, повторяем запрос…» ("The server is starting, retrying the request…") and retries by itself after `Retry-After` s (5 by default; the value is taken from the header, an integer) for up to 60 s from the first refusal, then «Сервер всё ещё запускается» ("The server is still starting") and a «Повторить» ("Retry") button. Rationale: a start with an index rebuild can take up to an hour (ADR 0058, D-26), an infinite loop would mislead; 60 s covers an ordinary start. Alternatives: infinite retry; no auto-retry (a button); 30 s. A write retry is safe: the refusal comes before the storage is touched.
4. [OURS] 503 `server_stopping`: «<Действие> не выполнено: сервер останавливается» ("<Action> failed: the server is stopping"), no auto-retry (the server is going away). A connection failure is distinguished by the kind of request. A write request (add, replace, delete) already sent and the link lost, or 504 `write_outcome_unknown` — the outcome is unknown: «<Действие>: нет подтверждения, исход неизвестен. Проверьте поиском по номеру» ("<Action>: no confirmation, outcome unknown. Check with a search by number") (ADR 0026, 0063), the action being «Сохранение» ("Saving") or «Удаление» ("Deletion"); there is no auto-retry of a write. Other requests (search, number check before adding, re-read), including without a connection: «<Действие> не выполнено: нет связи с сервером» ("<Action> failed: no connection to the server") (search: «Поиск не выполнен: нет связи с сервером» ("Search failed: no connection to the server")) and «Повторить»; no write was sent, "outcome unknown" is not shown.
5. [OURS] 503 `read_only`: «<Действие> не выполнено: база доступна только для чтения» ("<Action> failed: the database is read-only"); 500 `storage_error`: «<Действие> не выполнено: ошибка хранилища, обратитесь к оператору» ("<Action> failed: storage error, contact the operator"). The action is «Сохранение» (add, overwrite), «Удаление», «Поиск» (the message for search is «Поиск не выполнен»). Search counts as an action: if it did not complete because of `storage_error` (or the stream broke without a marker), the message is shown; there are no warnings on successful actions. No auto-retry: `read_only` is lifted by the operator, `storage_error` persists until restart. There are no details (errno, file) in responses (ADR 0053).
6. [DEFAULT] (D-81) Texts (Q-65): the brief's texts are shown verbatim as the reason after the prefix «<Действие> не выполнено:»; for `storage_error` the prefix is added because the brief gives only the reason; the value-error texts and the reason table are in `web-ui-shell`. Rationale: a single "action + reason" scheme for saving, deletion and search; «Сохранение не выполнено» ("Saving failed") does not suit deletion (Q-65), so the action in the prefix changes. Alternative: the same brief text for all actions. The form of a value error: «<Поле>: <причина>» at the field, by `field`, `reason`, `hint` from `invalid_input`, not by `message`; the value in the field is not erased; an unknown reason — «сервер отклонил значение (<код>)» ("the server rejected the value (<code>)"). Other refusals: «<Действие> не выполнено: ошибка сервера (<code>)» ("<Action> failed: server error (<code>)") and «Повторить».
7. [OURS] The page makes no background requests: no state polling, no token check; only requests triggered by a user action and the auto-retry of item 3.
8. **Changed by OD-6 (2026-10-28).** Q-160: the "number check" request before adding is replaced by a history request after 409 `number_known` (ADR 0090); the texts and the action «Сохранение» are unchanged.

## Alternatives considered
- Periodic server state polling: rejected (ADR 0011 item 6 [USER]; there is no state resource).
- Showing the `message` from the response: rejected, `message` is outside the contract (`http-api`).
- Auto-retry of `read_only`: rejected, the state does not go away by itself.

## Consequences
- `web-ui-shell`: requirements on refusals; `web-ui-flows` uses the common request layer: the message is shown by code and action.
- Q-39 is closed (item 2). Q-65 is closed for CUJ16 and value errors; the CUJ12 and overwrite texts are in `web-ui-flows`.
- D-80, D-81 — to the owner as a package.
